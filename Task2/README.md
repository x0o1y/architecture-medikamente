<details open>
<summary>Таблица «Требования FURPS+»</summary>

| Код | Требование | Комментарий |
| --- | --- | --- |
| F | Функциональные (Functionality) |  |
| F1 | Пациент самостоятельно записывается к специалисту через портал |  |
| F2 | Сотрудник ресепшена видит записи пациентов в системе |  |
| F3 | Сотрудник ресепшена получает сведения для напоминания пациенту и специалисту за день до приёма | Напоминание выполняется сотрудником ресепшена |
| F4 | CRM обеспечивает сбор и учёт данных пациентов |  |
| F5 | Единая система объединяет журналы приёма, учёт пациентов и оплату услуг | Существующая 1С сохраняется |
| F6 | Платёжный шлюз обеспечивает оплату услуг | Сценарий оплаты и состав передаваемых данных требуют уточнения |
| F7 | Система интегрируется с лабораторией анализов через API | Состав операций требует уточнения |
| F8 | На основе существующих Excel-файлов создаётся озеро данных |  |
| F9 | Данные используются для автоматизации BI-отчётности |  |
| F10 | Данные используются для подготовки моделей ML и сервисов AI, включая LLM | Конкретные модели и сценарии в постановке не определены |
| F11 | Пациент записывается к специалисту через мобильное приложение |  |
| F12 | Пациент получает автоматическое уведомление о записи через мобильное приложение или голосового робота |  |
| F13 | Пациент подтверждает или отменяет запись в ответ на уведомление |  |
| F14 | Ресепшен получает уведомление о подтверждении или отмене записи |  |
| F15 | Пациент просматривает свои анализы, заключения и договоры в мобильном приложении |  |
| F16 | Система позволяет помечать защищаемые данные тегами |  |
| F17 | Перед релизом автоматически проверяется работа с тегированными данными | Результат передаётся в мониторинг и алертинг |
| F18 | Система регистрирует действия доступа к данным для аудита |  |
| F19 | Система выявляет нетипичные действия пользователей |  |
| F20 | При несанкционированном доступе команда получает оповещение |  |
| U | Удобство использования (Usability) |  |
| U1 | Уточнить требования к удобству порталов и мобильного приложения | В постановке нет отдельных критериев удобства |
| R | Надёжность (Reliability) |  |
| R1 | При хранении и обработке обеспечивается целостность данных | Критерии контроля целостности требуют уточнения |
| R2 | Обеспечивается доступность данных | Допустимый простой, RPO и RTO в постановке не заданы |
| P | Производительность (Performance) |  |
| P1 | Система поддерживает пятикратный рост объёма данных | Исходный объём данных не указан |
| P2 | Система масштабируется при открытии филиалов, увеличении команды на десятки сотрудников и подключении мобильных пользователей | Число одновременных пользователей, интенсивность запросов и время ответа требуют уточнения |
| S | Сопровождаемость (Supportability) |  |
| S1 | Внесение изменений и развитие системы должны быть простыми и понятными для команды сопровождения | Критерии оценки требуют уточнения |
| S2 | Изменяемые параметры системы задаются конфигурацией без доработки кода | Перечень параметров нужно определить при проектировании |
| + | Безопасность и ограничения |  |
| +1 | Хранение и обработка конфиденциальных данных соответствуют применимым требованиям законодательства РФ | Компания работает с пациентами на территории РФ |
| +2 | Чувствительные данные защищены при хранении и обработке | Способы защиты определяются для каждой категории данных |
| +3 | Категории данных пациентов разделены по доменам |  |
| +4 | Для каждой категории данных определены роли RBAC или атрибуты ABAC, ограничивающие доступ сотрудников |  |
| +5 | Пациент не может получать данные других пациентов или выполнять недоступные ему операции | Ограничение применяется к порталу, мобильному приложению и API по мере их внедрения |
| +6 | API ограничивает раскрытие конфиденциальных полей и доступ внешних пользователей к данным и операциям | Правила применяются также при подключении новых партнёров |
| +7 | В аналитическом слое обеспечивается соблюдение принципов PbD |  |
| +8 | Чувствительные данные своевременно удаляются | Сроки хранения и условия удаления требуют уточнения |
| +9 | По запросу пациента прекращается обработка его данных | Основания и ограничения прекращения обработки требуют уточнения |
| +10 | При регистрации и записи на приём собираются только данные, необходимые для этих целей | Адрес прописки, место работы или учёбы и хронические заболевания исключаются из регистрационной анкеты; медицинские сведения при необходимости собираются отдельно при лечении |

<summary><h2>Roadmap</h2></summary>

Часть ролей могут совмещать технический директор и администратор сети.
Если компетенций или времени текущей команды недостаточно, привлекаются
дополнительные сотрудники или подрядчики.

Сроки ориентировочные, отсчитываются от начала проекта. Часть работ выполняется параллельно.
Ответственные и ресурсы — планируемые.

### Информация о компании

«Медикаменте» оказывает медицинские услуги в России. Сейчас у компании один
офис; открытие филиалов и расширение команды должны сопровождаться
автоматизацией процессов и поддержкой пятикратного роста объёма данных.

| Направление | Текущее состояние |
| --- | --- |
| Работа с пациентами | Регистрация пациентов, запись на приём, договоры, медицинские карты и учёт анализов ведутся вручную в Excel и сканах JPG/PDF на общем диске |
| Приём оплаты | Кассиры принимают платежи через ККМ и ведут двойной учёт в Excel и «1С:Бухгалтерия предприятия» |
| Бухгалтерский и кадровый учёт | «1С:Бухгалтерия предприятия» используется для учёта платежей, сотрудников, зарплат и подготовки налоговой документации |
| Учёт ТМЦ и закупок | «1С:Торговля и склад» работает в файловом режиме и интегрирована с «1С:Бухгалтерия предприятия» |

Системы размещены на собственном сервере Windows Server 2022 в офисе
компании. На нём работают файловый и почтовый серверы, Active Directory,
LDAP, DNS и DHCP. Сотрудники используют Excel, Outlook и 1С в локальной сети.

Доступ основан на доменной аутентификации. Дополнительного разграничения
доступа со стороны систем обработки данных нет. Чтение и изменение данных
не сопровождаются аудитом; внутренние потоки данных не контролируются.

и журналов специалистов.

<summary><h2>3. Защита данных</h2></summary>

### Способы защиты

Для конфиденциальных данных шифруются хранилища и резервные копии,
а передача выполняется по защищённым каналам. Доступ к расшифрованным данным
ограничивается служебными обязанностями сотрудника.

Маскирование скрывает часть значения при показе, например цифры телефона.
Полное значение остаётся в системе.

Обезличивание подготавливает аналитический набор так, чтобы по нему нельзя
было определить пациента. Одной замены ФИО на ID недостаточно: человека могут
выдать другие сведения. Поэтому идентифицирующие данные исключаются также
из текста и сканов, а точные даты и другие признаки при необходимости
заменяются менее подробными.

Синтетические данные — вымышленные пациенты и сведения для тестирования
вместо настоящих.

<details open>
<summary>Таблица «Способы защиты»</summary>

| № | Данные | Способы защиты |
| --- | --- | --- |
| 1 | ФИО и дата рождения пациента | Шифрование; маскирование в интерфейсах, где полные значения не нужны; замена на идентификатор в межсистемном обмене, если получателю не требуется ФИО |
| 2 | Телефон и электронная почта | Шифрование; маскирование при просмотре; исключение из аналитических наборов, которым контакты не нужны |
| 3 | Адрес регистрации, место работы или учёбы | Исключение из анкеты записи на приём; при обоснованном сборе в другом процессе — шифрование и ограничение доступа |
| 4 | Хронические заболевания, медицинские карты и результаты анализов | Сбор медицинских сведений в процессе оказания помощи; шифрование; передача лаборатории только необходимых полей; обезличивание перед использованием в аналитике |
| 5 | Записи пациента к специалистам | Шифрование; ограничение доступа ресепшеном и участвующими в приёме специалистами; агрегирование для аналитики без идентификации пациента |
| 6 | Договоры и сведения об оплате | Шифрование; маскирование реквизитов в представлениях, где они не нужны; обезличивание аналитических выгрузок |
| 7 | Кадровые сведения и начисления зарплаты | Шифрование; доступ уполномоченным сотрудникам бухгалтерии; агрегированные показатели без идентификации сотрудников для управленческой аналитики |
| 8 | Учётные данные сотрудников | Защищённый обмен с Active Directory / LDAP; ограничение доступа к хранилищу учётных данных; исключение паролей из журналов и выгрузок |
| 9 | ФИО в названиях файлов и папок | Замена ФИО идентификаторами; соответствие идентификатора пациенту или специалисту хранится отдельно с ограниченным доступом |

### Тегирование данных

В качестве примера каталога данных и тегов используется Apache Atlas.
Он хранит описание источников, классификации и связи между исходными данными
и производными наборами.<sup><a href="#source-1">[1]</a></sup> Сами медицинские документы и значения полей в каталог
не загружаются.

| № | Тег | Какие данные помечаются |
| --- | --- | --- |
| 1 | `PII` | ФИО, дата рождения, контакты, адрес и идентификаторы, связанные с человеком |
| 2 | `PHI` | Медицинские карты, хронические заболевания, результаты анализов и сведения о приёмах |
| 3 | `FIN` | Договоры, платежи и начисления |
| 4 | `HR` | Кадровые сведения и зарплаты сотрудников |
| 5 | `CREDS` | Описание полей и хранилищ учётных данных; без значений паролей и других секретов |

Одному объекту можно присвоить несколько тегов: например, файл результатов
анализов получает `PII` и `PHI`, а ведомость зарплаты — `PII`, `HR`
и `FIN`.

1. В каталоге регистрируются файлы, наборы документов и объекты 1С.
   Для новых баз и API описываются таблицы, поля и поля контрактов.
   Указываются источник, ответственный за данные и цель обработки.
2. Ответственный за данные подтверждает классификацию. Excel и сканы
   помечаются целиком; в структурированных источниках теги назначаются
   отдельным полям. Первичная разметка выполняется вручную через интерфейс Atlas.
3. При создании выгрузки или аналитического набора обработчик регистрирует
   результат и связь с источником через REST API Atlas.<sup><a href="#source-2">[2]</a></sup> Для этих связей
   включается наследование классификаций. Маскирование или замена ФИО
   идентификатором не снимают тег `PII`; снижение чувствительности требует
   проверки результата обезличивания.
4. По классификации определяются правила доступа, маскирования и передачи.
   В файловом хранилище ограничения применяются правами NTFS и группами AD,
   в новых приложениях — проверками доступа в API. Atlas хранит классификацию;
   применение правил в этих системах требует отдельной интеграции.
5. Автоматические тесты релиза проверяют запрет доступа к чужим данным,
   маскирование полей и сохранение тегов при выгрузках. Ошибки разметки
   и нарушения правил передаются в мониторинг и оповещения.

<summary><h2>4. Диаграммы потоков данных</h2></summary>

[DFD.drawio](DFD.drawio)

Диаграммы сохраняют исходные потоки данных. Красным обозначены предлагаемые меры защиты:
у процессов — минимизация и ограничения доступа, на стрелках — защита передачи,
у хранилищ — теги, шифрование, права доступа и аудит.

Логические DFD показывают бизнес-процессы и состав данных. Физические DFD
раскрывают исполнителей, ручные операции, программы и файлы.

```text
DFD.drawio
├── Контекст
├── Основные процессы
├── 1. Регистрация и запись
├── 2. Ведение медицинской карты
├── 3. Работа с лабораторными анализами
├── 4. Приём оплаты и бухгалтерский учёт
├── 5. Кадровый учёт и начисление зарплаты
└── 6. Учёт ТМЦ и закупок
```

</details>
